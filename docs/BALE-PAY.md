# اتصال پرداخت کیف پول بله به نقلی‌جان

**مستندات رسمی:** https://docs.bale.ai/#پرداخت و https://docs.bale.ai/miniapp

این اتصال بر پایهٔ Bot API رسمی بله است و **پرداخت کیف پول بله در مینی‌اپ** را پیاده‌سازی می‌کند. «createInvoiceLink» یک پارامتر فاکتور مینی‌اپ برمی‌گرداند، نه یک URL استاندارد درگاه که در هر مرورگری باز شود.

## معماری واقعی

۱. مشتری وارد حساب نقلی‌جان می‌شود، سبد خرید و نشانی ارسال را ثبت می‌کند و «بله‌پی» را انتخاب می‌کند.

۲. سفارش ابتدا با وضعیت \`PENDING\` و شناسهٔ \`bale:<orderId>\` ذخیره می‌شود. URL مستقیم مینی‌اپ بازو با \`startapp=<orderId>\` در پاسخ برمی‌گردد.

۳. مشتری وارد مینی‌اپ اصلی بله می‌شود که مدیر در BotFather به آدرس \`https://YOUR_DOMAIN/bale-pay\` تنظیم کرده است. این صفحه کتابخانهٔ \`https://tapi.bale.ai/miniapp.js\` را بارگذاری می‌کند.

۴. \`POST /api/payment/balepay/invoice\`، \`Bale.WebApp.initData\` را با HMAC-SHA-256 و تاریخ احراز هویت تأیید می‌کند. سرور مبلغ ثابت سفارش را از DB می‌خواند و از \`createInvoiceLink\` پارامتر فاکتور می‌گیرد. مبلغ با ضرب **تومان در ۱۰** به ریال تبدیل می‌شود.

۵. \`Bale.WebApp.openInvoice(invoiceParams)\` تنها در مینی‌اپ رسمی فراخوانی می‌شود. نتیجهٔ callback سمت کلاینت **هرگز ملاک ثبت پرداخت موفق نیست**.

۶. بله، رویداد \`pre_checkout_query\` را به وب‌هوک می‌فرستد. سرور مبلغ و موجودی را بررسی کرده و ظرف حداکثر ۱۰ ثانیه \`answerPreCheckoutQuery\` می‌دهد.

۷. وقتی \`message.successful_payment\` دریافت شد، تراکنش با \`inquireTransaction\` از API رسمی استعلام می‌شود؛ وضعیت \`paid\`، مبلغ ریالی، شناسهٔ تراکنش و سفارش بررسی می‌شوند. سپس ثبت پرداخت و کسر موجودی با تابع تراکنشی و idempotent انجام می‌شود.

۸. مینی‌اپ وضعیت سفارش را تنها با \`POST /api/payment/balepay/status\` و \`initData\` معتبر استعلام می‌کند؛ پرداخت «موفق» تنها بعد از تأیید سرور نمایش داده می‌شود.

## تنظیمات محرمانه (Vercel Environment Variables)

| نام | مقدار مورد نیاز |
| --- | --- |
| \`BALE_BOT_TOKEN\` | توکن اختصاصی بازو از **@botfather** در بله |
| \`BALE_WALLET_PROVIDER_TOKEN\` | توکن پرداخت کیف پول اختصاصی همان بازو |
| \`BALE_BOT_USERNAME\` | نام کاربری بازو، بدون \`@\` |
| \`BALE_WEBHOOK_SECRET\` | رشتهٔ تصادفی محرمانهٔ حداقل ۳۲ نویسه |
| \`BALE_MINIAPP_READY\` | فقط پس از تنظیم و آزمایش Mini App برابر \`true\` |
| \`BALE_WEBHOOK_READY\` | فقط پس از ثبت و آزمایش setWebhook برابر \`true\` |

**توجه:** توکن آزمایشی \`WALLET-TEST-1111111111111111\` در Production عمداً فعال نمی‌شود. این توکن برای آزمایش است و وجهی جابه‌جا نمی‌کند.

## پیکربندی مینی‌اپ در بله

در بازوی \`@botfather\` یک بازو بساز، توکن پرداخت کیف پولی را بگیر و **مینی‌اپ اصلی (Main Mini App)** آن را روی نشانی HTTPS واقعی زیر تنظیم کن:

\`https://YOUR_DOMAIN/bale-pay\`

کاربر از لینک رسمی \`https://ble.ir/BOT_USERNAME?startapp=ORDER_ID\` وارد می‌شود. تغییر خودسرانهٔ این لینک به یک درگاه بیرونی مطابق مستندات نیست.

## وب‌هوک (Webhook)

سرور بله باید رویدادهای بازو را روی URL مخصوص پروژه دریافت کند:

\`https://YOUR_DOMAIN/api/payment/balepay/webhook?key=YOUR_BALE_WEBHOOK_SECRET\`

این URL را با متد رسمی \`setWebhook\` و توکن بازو از سمت یک محیط مدیریت امن ثبت کن. از ثبت توکن‌ها در GitHub، README عمومی، لاگ‌ها و اسکرین‌شات خودداری کن.

پروتکل به‌صورت رسمی هدر امضای وب‌هوک را مستند نکرده است؛ بنابراین مسیر از **کلید تصادفی مخفی** استفاده می‌کند. فارغ از آن، سرور برای هر پرداخت موفق یک استعلام مستقل \`inquireTransaction\` می‌زند. برای بازویی که وب‌هوک دیگری دارد، قبل از تغییر URL برنامهٔ تجمیع رویدادها را مشخص کن؛ \`setWebhook\` ممکن است تنظیم فعلی را جایگزین کند.

## موارد ضروری قبل از Production

- آزمایش کامل در کلاینت واقعی بله روی Android و Web
- بررسی مبالغ ریالی، تکرار رویدادها، برگشت از پرداخت و انقضای سفارش
- بررسی تراکنش‌های \`PENDING\`، کنترل موجودی و صف مصالحهٔ مالی
- عدم ذخیرهٔ شماره کارت، اطلاعات بانکی یا توکن در فرم‌های عمومی
- \`BALE_MINIAPP_READY\` و \`BALE_WEBHOOK_READY\` تا پیش از آزمایش صحیح **false / unset** بمانند
- در صورت تغییر تنظیم webhook، اثر آن روی دیگر کارکردهای بازو بررسی شود

## محدودیت فعلی

بدون بازوی ایجادشده، توکن کیف پول واقعی، پیکربندی مینی‌اپ و ثبت وب‌هوک، هیچ پرداخت واقعی برای بله فعال نیست. صرف وجود کد در GitHub یا موفقیت Build به معنای تأیید انتقال پول نیست.
